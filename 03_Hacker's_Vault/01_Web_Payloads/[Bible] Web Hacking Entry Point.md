
**Phase 1: 표면 분석 (어디를 찌를 것인가?)**

- [ ] URL 파라미터가 있는가? (`?id=1`)
    
- [ ] 로그인/검색 등 입력 폼(Input)이 있는가?
    
- [ ] 패킷을 잡았을 때 조작 가능한 Header가 있는가? (`X-Forwarded-For` 등)
    

**Phase 2: 탐침 던지기 (무엇으로 반응을 볼 것인가?)**

- [ ] `'` 또는 `"` 입력 ➡️ **500 에러 / DB 오류 발생?** 
       👉 [[Methodology - SQLi]]
    
- [ ] `<h1>test</h1>` 또는 `"><script>alert(1)</script>` 입력 ➡️ **화면에 태그가 그대로 렌더링(동작) 됨?**
      👉 [[Methodology - XSS]]
    
- [ ] `; ls` 또는 `| id` 입력 ➡️ **서버 명령어가 실행됨?** 👉 `[[Methodology_Command_Injection]]` 로 진입
    
- [ ] `../../../etc/passwd` 입력 ➡️ **시스템 파일이 읽힘?** 👉 `[[Methodology_Path_Traversal]]` 로 진입
    

**Phase 3: 멘탈 붕괴 시 (아무것도 안 통할 때)**

- [ ] 오픈소스 기반인가? ➡️ 해당 버전의 알려진 취약점(CVE) 검색.
    
- [ ] 소스코드가 주어졌는가? ➡️ 파라미터가 백엔드에서 어떻게 필터링되는지 소스코드 로직 분석부터 다시 시작.
